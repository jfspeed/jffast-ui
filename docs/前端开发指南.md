# 疾风（jffast）前端开发指南

> 公开版前端开发指南：面向所有使用/贡献 jffast-ui（Base 前端）的开发者。
> 适用于 `jffast-ui` 及其 `@jfspeed/shared` 公共包。

---

## 1. Monorepo 架构

前端采用 **npm workspaces** 管理公共代码与应用代码：

| 目录/包                        | 说明                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `shared/`（`@jfspeed/shared`） | 公共组件、hooks、utils、layouts、store、style、locales、config、constants、types、api/core |
| `src/`                         | Base 应用代码（pages、router、api、assets、create-app.ts）                                 |

- Base 应用样式框架层文件（`.ts`）尽量不动，业务代码用 `.js`
- 页面统一使用 `<script setup>` Composition API
- 应用可基于 `createBaseApp()` 二次封装，复用同一套 `@jfspeed/shared`

## 3. 技术约束

- UI 框架：**TDesign Vue Next**，组件前缀 `t-`
- 样式：**less**；入口覆盖见 `shared/src/style/`
- 路由：**History 模式**，模块配置放 `src/router/modules/`
- 构建：Vite

## 4. API 层

### 标准 CRUD：`createCrud`

```javascript
// src/api/demo.js
import { createCrud } from '@/api/core/crud';
export const demoApi = createCrud('/demo/example');
```

`createCrud(baseUrl, options)` 默认提供：`create` / `update` / `delete` / `detail` / `page` / `list`（`list` 对应后端 `/all`），可传 `options` 覆盖或追加方法（见 `shared/src/api/core/crud.js`）。**不自带 `batchDelete`**：批量删除不是通用能力（后端只有个别资源实现），需要的资源在自己的 `options` 里显式声明。

### 自定义 API：`http` 适配层

```javascript
import { http } from '@/api/core/crud';
http.get(url, params, config);
http.post(url, data, config);
http.put(url, data, config);
http.delete(url, data, config);
http.upload(url, formData, config); // multipart/form-data
http.download(url, params, filename); // blob 下载
```

- 请求头 Token 格式：`token: {token}`（Sa-Token 语法）
- 统一响应拦截在 `shared/src/utils/request.ts`，错误按 `R` 结构处理

## 5. 页面标准结构

页面放 `src/pages/{module}/{pageName}/`，列表页 `index.vue` + 表单弹窗 `save.vue`：

```vue
<!-- src/pages/demo/demoExample/index.vue -->
<script setup>
import { ref } from 'vue';
import { useTable } from '@/hooks/useTable';
import { demoApi } from '@/api/demo';
import saveDialog from './save.vue';

const {
  loading,
  pageParams,
  searchForm,
  handleSearch,
  resetSearch,
  fetchData,
  handlePageChange,
  handleSizeChange,
  add,
  edit,
  show,
} = useTable(demoApi);
const saveRef = ref(null);

const columns = [
  { colKey: 'title', title: '标题', ellipsis: true },
  { colKey: 'status', title: '状态', width: 100 },
  {
    colKey: 'op',
    title: '操作',
    width: 200,
    cell: (h, { row }) =>
      h('div', [
        h('a', { onClick: () => show(row) }, '查看'),
        h('a', { onClick: () => edit(row) }, '编辑'),
        h('a', { onClick: () => handleDelete(row.id) }, '删除'),
      ]),
  },
];

function handleDelete(id) {
  DialogPlugin.confirm({
    header: '确认删除？',
    body: '删除后不可恢复',
    onConfirm: async () => {
      await demoApi.delete(id);
      MessagePlugin.success('删除成功');
      fetchData();
    },
  });
}

onMounted(fetchData);
</script>

<template>
  <t-card>
    <t-form :data="searchForm" layout="inline" @submit="handleSearch" @reset="resetSearch">
      <t-form-item label="标题" name="title">
        <t-input v-model="searchForm.title" clearable />
      </t-form-item>
      <t-button theme="primary" type="submit">查询</t-button>
      <t-button theme="success" @click="add">新增</t-button>
    </t-form>
  </t-card>
  <t-card>
    <t-table :loading="loading" :data="pageParams.list" :columns="columns" row-key="id" />
    <t-pagination
      :current="pageParams.pageNum"
      :page-size="pageParams.pageSize"
      :total="pageParams.total"
      @current-change="handlePageChange"
      @page-size-change="handleSizeChange"
    />
  </t-card>
  <save-dialog v-if="dialog.save" ref="saveRef" @success="fetchData" @closed="dialog.save = false" />
</template>
```

```vue
<!-- src/pages/demo/demoExample/save.vue -->
<script setup>
import { computed } from 'vue';
import { useI18n } from 'vue-i18n';

import api from '@/api/demo';
import { useForm } from '@/hooks/useForm';

const emit = defineEmits(['success', 'closed']);
const { t } = useI18n();

const { visible, mode, isSaving, formRef, form, rules, open, setData, submit } = useForm({
  defaultForm: { title: '', status: 1 },
  rules: { title: [{ required: true, message: '请输入标题' }] },
});

// useForm 内置的 titleMap 是**中文常量**（不随语言切换）；需要 i18n 时在页面侧用 computed 覆盖
const titleMap = computed(() => ({ add: t('common.add'), edit: t('common.edit'), show: t('common.view') }));

async function handleConfirm() {
  // submit 接收的是「带 create / update 的 api 对象」，不是单个函数
  const res = await submit(api.demoExample);
  if (res && res.code === 200) {
    emit('success');
    visible.value = false;
  }
}

defineExpose({ open, setData });
</script>

<template>
  <t-dialog
    :header="titleMap[mode]"
    v-model:visible="visible"
    :confirm-btn="{ content: t('common.dialogSave'), loading: isSaving }"
    @confirm="handleConfirm"
  >
    <t-form ref="formRef" :data="form" :rules="rules">
      <t-form-item label="标题" name="title">
        <t-input v-model="form.title" />
      </t-form-item>
      <t-form-item label="状态" name="status">
        <t-switch v-model="form.status" :custom-value="[1, 0]" />
      </t-form-item>
    </t-form>
  </t-dialog>
</template>
```

- 表格逻辑用 `useTable`，表单逻辑用 `useForm`（`shared/src/hooks/`）
- `useForm` 返回 `visible / mode / isSaving / formRef / form / rules / titleMap / open / close / setData / resetForm / submit`；
  `submit` 自带提交锁（校验阶段即占用 `isSaving`），连点只提交一次
- `save.vue` 通过 `defineExpose` 暴露 `open`/`setData`
- **路由页**（被菜单或静态路由直接挂载的 `index.vue`，如 `flow/task/todo.vue`）必须写
  `defineOptions({ name: 'Xxx' })`：`Xxx` 与静态路由 `name`、后端菜单 `upperFirst(sys_menu.path)` 一致。
  页签保活 `:include` 用的是 `route.name`，Vue 却按**组件名**匹配，缺了不报错、只是保活静默失效
- 删除确认用 `DialogPlugin.confirm()`（不是 `MessagePlugin.confirm`）

## 6. 状态管理（Pinia）

- 状态集中在 `shared/src/store/modules/`，从 `@/store` 导入实例
- 用户态、权限、设置、多页签、通知等已有模块，新状态按同样模式拆分
- 组件内避免大量非响应式的全局变量，需要跨组件共享的状态写入 store

```javascript
import { useUserStore } from '@/store';
const userStore = useUserStore();
```

### 6.1 登出流程（单一入口）

- 登出必须按顺序执行：① 调后端 `auth.logout()` 吊销会话（失败不阻塞）→ ② `user.logout()` 清用户态与 localStorage → ③ `permissionStore.restoreRoutes()` 复位动态路由 → ④ `router.replace(buildLoginRoute(...))` 回登录页
- 只调后端登出会留下 Pinia 内存态、localStorage 与已注入的动态路由，同标签页换账号登录会沿用上一账号的菜单 / 权限
- 动态路由只有一个来源（`permissionStore`）；页面 / 组件不得自行 `router.addRoute` 或手工清空路由表

## 7. 国际化（i18n）

- 文案统一在 `shared/src/locales/lang/zh_CN.json` / `en_US.json` 维护
- 语言切换组件 `LanguageSwitcher`，语言入口见 `shared/src/locales/useLocale.ts`
- 新页面文案需同时登记中英文 key，禁止在模板中硬编码用户可见文案
- **词条命名**：共享动作词（新增/编辑/删除/查询/导出/导入/下载/取消…）挂 `common.*`；页面文案挂 `pages.<域>.<页面>.*`（如 `pages.system.post.postCode`、`pages.system.task.statusMap`），禁止在页面域下重复定义动作词
- **columns / options 等文案型配置必须 computed 化**（`const columns = computed(() => [...])`），语言切换即时生效；禁止模块加载时一次性求值成常量
- 词条已全量覆盖内置页面，新增用户可见文案当次补齐中英双语 key

## 8. 样式规范

- 使用 less，入口见 `shared/src/style/index.less`，变量见 `variables.less`
- 优先使用 TDesign 主题变量与 `t-` 类，不过度自定义
- 页面级覆盖样式用 scoped（`<style scoped lang="less">`），key 遵循 BEM 或 TDesign 类前缀

## 9. 权限指令

- 按钮级权限用 `v-permission` 指令（`shared/src/utils/permission.js`），超管自动放行：

```vue
<button v-permission="'demo:example:add'">新增</button>
```

- 逻辑判断可用 `hasPermission` / `hasRole` 工具函数
- 权限标识与后端 `@SaCheckPermission` 保持一致：`模块:业务:操作`

## 10. 组件/Hooks 目录准入

- **全局组件**：仅放入 `shared/src/components/`，需满足跨项目/跨页面复用，否则放页面 `components/` 局部
- **可复用逻辑**：抽象为 `shared/src/hooks/` 自定义 hook，避免各页面重复实现
- 新增全局组件/入口需要同时维护类型声明与文档

## 11. 安全约束

- 密码字段必须 **RSA 加密后提交**（配合后端 `RSAUtil`）；加解密函数见 `shared/src/utils/crypto.js`（**无 `tool.js`**）
- 前后端加解密统一走 `crypto.js`（底层 **jsencrypt**，RSA PKCS#1 v1.5；不是 Web Crypto），不引入已归档的 crypto-js
- 敏感字段（手机号/身份证/邮箱）展示前脱敏，可通过 `@SensitiveMask`（后端）+ 前端脱敏函数配合
- Token 存内存/授权态管理，不写入 localStorage 明文敏感信息
- WebSocket 认证优先走握手子协议 `Sec-WebSocket-Protocol`；仅当子协议握手失败时对**本次连接**降级为 `?token=`，重连必须回到子协议（避免 token 永久进入 URL / 代理日志）
- 社交账号绑定只提交后端回调签发的 `bindTicket`，不得把客户端侧的社交用户资料直接回传；回调必须原样透传 `state`
- 管理员重置密码后的一次性明文口令只在响应中出现一次：前端须用可复制的弹窗展示，关闭即不可再查看，不得落 localStorage / 日志
- 登录回跳 `redirect` 只走 `shared/src/utils/login-redirect.ts`（编码 / 解码 / 站内白名单一处收敛），禁止在页面或拦截器里自行拼 `encodeURIComponent`：回跳地址必须取「已完成首次导航的当前路由或浏览器地址栏」，冷启动时取错会把回跳覆盖成 `/`（2026-09-29 缺陷实证）

## 12. 前端测试规范

### 12.1 单元测试（Vitest）

- 单元测试统一用 **Vitest**（`vitest` + `happy-dom`），配置在项目根 `vitest.config.ts`
- 测试文件与被测代码同目录命名：`*.test.ts` / `*.test.js`（如 `shared/src/utils/permission.test.ts`）
- 跑法：`npm test`（`vitest run`）；监听：`npm run test:watch`
- 优先覆盖**纯逻辑与共享层**：`shared/src/utils/*`、`constants`、权限判断、加解密边界
- 组件测试需要 `@vue/test-utils` 时再引入；起步阶段不强制
- 测试内显式 `import { describe, it, expect, vi } from 'vitest'`，不依赖全局注入
- 可 mock 掉 Pinia / 路由（`vi.mock('@/store', ...)`），不要起完整应用

### 12.2 端到端（Playwright）

- 浏览器自动化测试用 Playwright，配置在项目根 `playwright.config.ts`，脚本统一放 `e2e/` 目录（用例说明见 `e2e/README.md`）
- 跑法：`npm run test:e2e`（即 `playwright test`）；首次需 `npx playwright install chromium` 下载浏览器
- 默认访问 `http://localhost:7201`，可用 `E2E_BASE_URL` 覆盖；测试账号用 `E2E_USERNAME` / `E2E_PASSWORD` 环境变量注入，**禁止把真实凭据写进仓库**
- 必须打开真实浏览器验证页面效果，不得仅用接口调用代替前端验证
- 页面加载等待用 `wait_until: 'networkidle'`，元素断言优先用 locator 断言，避免固定时长 sleep
- 失败用例的 trace / 截图 / 报告统一输出到 `e2e/.artifacts/`（本地临时产物，测试截图用完即删，禁止留在仓库）

### 12.3 类型检查（vue-tsc）

- 门禁命令：`npm run build:type`（即 `vue-tsc --noEmit`），**必须 0 错**；CI 中为硬失败步骤，不加 `continue-on-error`
- `tsconfig.json` 的 `include` 必须覆盖 `src/**/*` 与 `shared/**/*`（含 `*.vue`），`paths` 必须与 `vite.config.ts` 别名一一对齐，否则类型检查结果不可信
- 补类型约定：`ref({})` / `reactive({})` 给内联类型参数；`ref([])` 给元素类型；索引访问对象补 `Record<string, T>`；`catch (e)` 显式收窄
- TDesign 组件事件的内联箭头函数也要标参（如 `@current-change="(p: number) => …"`），否则跨 TS 版本会退化为隐式 `any`

## 13. 新页面开发流程（与代码生成器配合）

1. 后端按《开发规范》建表/生成代码并注册模块
2. 前端用代码生成器产出 `api/{module}.js` + `pages/{module}/{pageName}/index.vue` + `save.vue` + 路由片段
3. 在 `src/router/modules/` 注册路由
4. 业务定制：字段校验、关联查询、按钮权限（`v-permission`）、特殊交互
5. 验证：页面 CRUD 正常、语言 key 齐全、权限正确、问题用 Playwright 回归

内置参考页面/按钮（可直接对照实现）：

- 岗位管理：`src/pages/system/post/`（列表 + 表单弹窗，权限 `system:post:*`）
- 异步任务：`src/pages/system/task/`（进度/结果文件下载，权限 `system:task:*`）
- 通知发送：`src/pages/system/notification/send.vue`（站内信 + 邮件/短信通道多选）
- 导入导出按钮：用户页（导出/导入/下载模板/异步导入导出）、日志页（导出），配合 `http.upload` / `http.download`

## 14. 全局水印

- 组件 `shared/src/components/Watermark.vue`（TDesign `t-watermark`），应用入口 `src/App.vue` 全局挂载，登录后自动显示
- 默认内容两行：应用名（`VITE_APP_TITLE`，默认「疾风管理系统」）+ 「用户名 · 时间」；时间每 30s 刷新，便于截图追溯
- Props：`enabled`（默认 true）、`content`（自定义行数组，传入即覆盖默认内容）、`zIndex`（默认 6000，需盖过弹层）
- 水印层铺满视口、`pointer-events: none` 不拦截交互、`removable: false` 不可被移除；窗口 resize 防抖后自动重建

## 15. 移动端适配

- 断点口径统一在 `shared/src/hooks/useResponsive.ts`（`RESPONSIVE_BREAKPOINTS`）：**手机 ≤ 768px**、**平板 768 < 宽度 ≤ 960px**、**桌面 > 960px**；JS 判定与样式媒体查询共用同一套口径（样式侧见 `shared/src/style/layout.less`）
- 手机：侧边栏收起为抽屉菜单、顶栏压缩、内容区横向滚动；平板：保留侧栏、布局最小宽与栅格适配；桌面：不做任何响应式改动
- 业务代码通过 `useResponsive()` 取 `isMobile` / `isTablet` / `isDesktop` / `width`（resize 防抖 150ms、多组件共享一个监听，需在 setup 内调用），禁止散写 `window.innerWidth`

> 提示：以上规范适用于本开源版本；基于本框架的二次开发扩展规范由各自项目自行维护。
